How it works

The clip pipeline hinges on a registered source recording — an org-scoped R2 object whose location is written into the iso_recordings table via the internal registry (POST /v1/internal/recordings/register, service-token gated). Any ingest protocol — SRT, RTMP, WHIP, MoQ, or direct upload — can deposit bytes and register their location, making them immediately clip-able.

When the agent calls POST /v1/clips, the clip engine (a Cloudflare Media Transformations worker) resolves the source to a presigned R2 URL, transcodes the requested time window with env.MEDIA, and writes the result into the wave-clips R2 bucket under <org>/clips/<clipId>/. Private clips are served via HMAC-signed delivery URLs that wave-media-edge verifies at request time against MEDIA_SIGNING_KEY.
